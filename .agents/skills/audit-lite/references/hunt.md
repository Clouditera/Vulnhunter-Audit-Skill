# hunt 任务书（单轮）

系统性精读**本轮指定的一个功能点**，找出值得复核的风险假设（HYP）。

## 做什么
1. 先读 `.vulnforge/coverage.md` 的未读清单，精读主会话指定的功能点（一个模块/一条数据流，别贪多）
2. 沿真实数据流读：入口（参数/请求/文件输入）→ 传播 → 校验（有没有、够不够）→ Sink（命令执行/SQL/文件读写/危险调用）
3. 对照 `knowledge/security.md` 的项目安全准则：符合它定义的才算风险，排除项不提
4. 每个可疑点：确认 file:line 锚点 + 一句话主张（哪段输入能造成什么后果）

## 产出
1. **追加** `.vulnforge/hyps.jsonl`：每个风险点一行 JSON
   `{"id":"H<序号>","body":"<file:line 主张>","tag":"hunt<轮号>","state":"new","finding_id":null}`
   id 取当前最大序号+1；不要改别人的行
2. **更新** `.vulnforge/coverage.md`：本轮真实读过的行加入「已读」（file: 行区间），「未读」相应缩小。**只记真读过的行**
3. 本轮没有新发现就如实说，不凑数

## 边界
只做静态精读，不做动态执行、不改被测源码。HYP 是待复核的怀疑，成立与否由 verify 裁决。
